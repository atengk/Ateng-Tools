# Specification: Developer Utilities Suite (Snowflake ID Analyzer, cURL Converter, JSON to Entity, SQL DDL to Entity)

## Problem Statement

During modern full-stack and backend software development, engineers encounter repetitive, context-switching data conversion tasks every day:
1. **Snowflake ID Inspection & Generation**: Distributed IDs generated by Snowflake algorithms are 64-bit opaque integers (e.g. `1702983748293849088`). When investigating database anomalies, sorting inconsistencies, or distributed concurrency issues, developers cannot directly tell when the record was generated, which datacenter/machine node issued it, or its sequence number without writing custom code or scripts.
2. **cURL Command Translation & Inspection**: When debugging APIs or reproducing network issues from browser Network DevTools, Postman, or server logs, developers copy requests as `curl` bash commands. However, integrating this request into an automated script, frontend client (Axios, Fetch), or backend service (Java HttpClient) requires tedious manual extraction of headers, query parameters, auth tokens, and request bodies.
3. **JSON to Entity / Type Definitions**: When integrating third-party APIs or frontend-backend DTOs, engineers receive JSON payloads and must hand-write Java POJO/DTO classes (with Lombok and Jackson annotations) or TypeScript interfaces. Manually mapping types, converting snake_case to camelCase, and creating nested inner classes is slow and error-prone.
4. **SQL DDL to Java Entity & TS Interface**: When starting a new feature from database schema scripts (`CREATE TABLE`), developers have to manually create corresponding Java Entity classes for ORMs (like MyBatis-Plus) and matching TypeScript interface types for frontend forms and tables, repeatedly adding annotations (`@TableName`, `@TableId`, `@TableLogic`), mapping types (`DATETIME` to `LocalDateTime`), and copying column comments.

Existing online tools for these tasks are often scattered across third-party ad-heavy websites that present serious security risks of leaking company API endpoints, authentication headers, database schemas, and production IDs.

## Solution

A cohesive suite of four high-frequency client-side developer utility tools integrated into the **Ateng-Tools** toolbox under the `Development` category, adhering to ADR 0001:
1. **Snowflake ID Analyzer**: A 64-bit ID analyzer and generator supporting binary bit decomposition, timestamp/datacenter/worker/sequence decoding, configurable epochs (default Twitter), 5+5+12 and 10+12 layouts, single-ID visual inspection cards, and multiline batch analysis tables.
2. **cURL Converter**: A cURL command tokenizer and code generator that translates bash cURL commands into clean JavaScript Axios, modern Fetch, and Java 11/21 HttpClient code, coupled with a visual inspection table for Query Params, Headers, Request Body, and Authentication.
3. **JSON to Entity Converter**: A deep recursive schema inferrer that translates arbitrary JSON into Java DTO classes (with Lombok, Jackson `@JsonProperty`, static inner classes, and camelCase) and TypeScript interfaces with optional fields.
4. **SQL DDL to Entity Converter**: A MySQL 8.x `CREATE TABLE` parser that outputs standard Java Entity classes configured for MyBatis-Plus (`@TableName`, `@TableId(type = IdType.ASSIGN_ID)`, `@TableLogic`, `LocalDateTime`, Javadoc comments) alongside synchronized TypeScript interfaces.

All four tools execute **100% in the user's browser locally** with zero external network requests, preserving complete data confidentiality.

## User Stories

### Snowflake ID Analyzer
1. As a backend developer, I want to paste a 64-bit Snowflake ID, so that I can see the exact date, time (to millisecond precision), and relative time it was created.
2. As a distributed systems engineer, I want to inspect the 64-bit binary representation partitioned into color-coded segments (Sign bit, Timestamp bits, Datacenter ID bits, Worker ID bits, Sequence bits), so that I can verify bitwise alignment and algorithm correctness.
3. As a developer, I want to switch between standard Twitter 5+5+12 bit layout (5-bit datacenter + 5-bit worker) and 10+12 bit layout (10-bit worker), so that I can inspect IDs from different company implementations.
4. As a developer, I want to configure a custom Epoch timestamp (in milliseconds or ISO datetime), so that IDs generated with custom base epochs decode to the correct historical timestamps.
5. As an engineer investigating an incident, I want to paste a batch of multiple Snowflake IDs (one per line), so that I can see a sortable table detailing the timestamp, machine ID, and sequence for each record.
6. As a QA engineer, I want a Snowflake ID generator panel where I can specify timestamp, datacenter ID, worker ID, and sequence, so that I can generate mock IDs for test fixtures.
7. As a developer, I want an error notice when entering an invalid or non-numeric ID, so that I am prevented from viewing corrupt calculations.

### cURL Converter
8. As a frontend developer, I want to paste a `curl` command copied from Chrome DevTools, so that I can instantly get a clean JavaScript Axios snippet ready to paste into my API client file.
9. As a developer, I want to convert a `curl` command to standard modern JavaScript `fetch` code, so that I can use it in vanilla scripts or modern web runtimes without third-party dependencies.
10. As a Java developer, I want to convert a `curl` command to `java.net.http.HttpClient` (JDK 11+/21) code, so that I can quickly reproduce third-party HTTP requests in backend unit tests or services.
11. As a developer debugging an issue, I want to view a "Request Inspection" tab that extracts HTTP Method, URL, Query Parameters table, Headers table, and Request Body into dedicated visual cards, so that I can quickly verify authentication tokens and query arguments.
12. As a developer, I want the cURL parser to robustly handle multiline commands with line-continuation backslashes (`\`) or carets (`^`), so that raw terminal commands paste without syntax errors.
13. As a developer, I want the parser to handle both `-H` headers and `-d`/`--data`/`--data-raw` payload formats, including auto-formatting JSON request payloads.
14. As a developer, I want to click a "Load Sample" button, so that I can immediately experiment with complex cURL formats including headers and POST data.
15. As a developer, I want one-click copy buttons for every generated code snippet, so that I can quickly paste the result into my IDE.

### JSON to Entity Converter
16. As a Java backend developer, I want to paste a JSON response from an external API, so that I can generate a Java class complete with `@Data`, `@Builder`, `@NoArgsConstructor`, and `@AllArgsConstructor` Lombok annotations.
17. As a backend developer, I want JSON keys with snake_case naming to be automatically converted to camelCase field names in Java, accompanied by `@JsonProperty("original_key")` annotations, so that JSON serialization works seamlessly.
18. As a backend developer, I want nested JSON objects to be converted to `public static class` nested inner classes, so that a complex payload is contained in a single self-contained file.
19. As a backend developer, I want ISO-8601 date strings to be inferred as `LocalDateTime`, and long integer identifiers to be inferred as `Long`, so that Java types accurately reflect domain constraints instead of generic strings and integers.
20. As a frontend developer, I want to switch target language to TypeScript, so that I can generate matching TypeScript `interface` definitions with nested types and nullable annotations.
21. As a developer, I want configurable options for Root Class Name and Package Name, so that the generated code directly matches my project structure.

### SQL DDL to Entity Converter
22. As a Java backend developer, I want to paste a MySQL `CREATE TABLE` DDL statement, so that I can generate a complete MyBatis-Plus Entity class with `@TableName("table_name")`.
23. As a backend developer, I want the primary key column (e.g. `id BIGINT`) to be recognized and annotated with `@TableId(type = IdType.ASSIGN_ID)`, so that snowflake ID assignment is configured automatically.
24. As a backend developer, I want logical deletion columns named `deleted` to be annotated with `@TableLogic`, so that soft delete behavior is handled natively by MyBatis-Plus.
25. As a backend developer, I want SQL column `COMMENT` strings to be extracted into clean Javadoc `/** ... */` comments above each field, so that the generated Java code is fully documented.
26. As a backend developer, I want MySQL types (`BIGINT`, `INT`, `TINYINT`, `VARCHAR`, `TEXT`, `DATETIME`, `DECIMAL`) to map deterministically to Java types (`Long`, `Integer`, `Integer`, `String`, `String`, `LocalDateTime`, `BigDecimal`).
27. As a full-stack engineer, I want a tab showing the equivalent TypeScript Interface for the table, so that I can use the same model in frontend Vue components.
28. As an international developer, I want all four tools to support both English and Simplified Chinese (zh-CN) localization across all labels, placeholders, and tooltips.

## Implementation Decisions

- **Architectural Placement & Category**:
  All four tools reside in their respective directories under `src/tools/` and are registered in `src/tools/index.ts` under the `Development` category:
  - `src/tools/snowflake-id-analyzer/` (`/snowflake-id-analyzer`)
  - `src/tools/curl-converter/` (`/curl-converter`)
  - `src/tools/json-to-entity/` (`/json-to-entity`)
  - `src/tools/sql-ddl-to-entity/` (`/sql-ddl-to-entity`)
- **Zero External Backend (ADR 0001)**:
  All parsing and code generation algorithms execute strictly client-side inside the browser memory. No network requests are made.
- **Pure Deterministic Service Layer**:
  Each tool is divided cleanly into:
  - `*.models.ts`: Type declarations and configuration interfaces.
  - `*.service.ts`: Pure algorithmic business logic (BigInt bit manipulations, lexical tokenizers, AST schema traversals).
  - `*.service.test.ts`: Vitest unit tests covering edge cases.
  - `*.vue`: Naive UI components providing reactive state, split-pane layouts, and code highlighters.
- **Type Inferences & Conventions**:
  - Snowflake IDs: Handled via native JavaScript `BigInt` to prevent 64-bit integer precision loss.
  - JSON to Java: Class generation outputs standard Spring Boot 3 / Lombok annotations without requiring external runtime generators.
  - SQL DDL Parser: Lightweight stateful SQL lexer parsing MySQL table names, columns, data types, lengths, primary keys, and comments.

## Testing Decisions

- **Core Seam**:
  The primary testing seam across all four tools is the **Service Layer (`*.service.ts`)**.
  Testing against the service functions tests the highest possible level of business behavior while keeping tests 100% deterministic, headless, and fast.
- **Service Seam Test Coverage**:
  1. `snowflake-id-analyzer.service.test.ts`:
     - Test standard Twitter Snowflake parsing (timestamp, datacenter, worker, sequence).
     - Test 10+12 worker layout.
     - Test custom Epoch offset calculation.
     - Test batch multiline ID parsing.
     - Test reverse generation from components back to 64-bit ID.
     - Test error handling for malformed / negative / out-of-range inputs.
  2. `curl-converter.service.test.ts`:
     - Test basic GET request with query params.
     - Test POST request with JSON body and custom headers (`-H`, `--data`).
     - Test multiline shell syntax with escaped newlines (`\`).
     - Test Basic Auth (`-u user:pass`) and Bearer Token header parsing.
     - Test code generation accuracy for Axios, Fetch, and Java HttpClient.
  3. `json-to-entity.service.test.ts`:
     - Test primitive types (strings, numbers, booleans, null).
     - Test ISO datetime strings inferring `LocalDateTime`.
     - Test integer vs floating-point number inference.
     - Test nested objects generating static inner classes.
     - Test array of objects unifying schemas.
     - Test snake_case to camelCase conversion and `@JsonProperty`.
     - Test TypeScript interface generation.
  4. `sql-ddl-to-entity.service.test.ts`:
     - Test standard MySQL `CREATE TABLE` parsing with backticks and comments.
     - Test primary key extraction with `@TableId(type = IdType.ASSIGN_ID)`.
     - Test logical delete `deleted` with `@TableLogic`.
     - Test type mapping rules (`BIGINT` -> `Long`, `DATETIME` -> `LocalDateTime`, `DECIMAL` -> `BigDecimal`).
     - Test table comment and column comments extraction into Javadoc.
     - Test generated TypeScript interface output.
- **Prior Art**:
  Follows existing test suites in `src/tools/` (such as `mybatis-sql-converter.service.test.ts` and `xml-formatter.service.test.ts`) executed via `pnpm test:unit`.

## Out of Scope

- Direct database connection or live schema introspection (pure DDL text parsing only).
- Remote cURL request execution / HTTP proxying (code generation and visual inspection only).
- Generating full Maven/Gradle project scaffolding (focuses on single entity/DTO files and inner classes).
- Parsing non-MySQL DDL (e.g. Oracle / SQL Server specific procedural DDL).

## Further Notes

- All four tools will be localized with full English and Simplified Chinese translations in `locales/en.yml` and `locales/zh.yml`.
- Dependencies already existing in `package.json` (`change-case`, `date-fns`, `naive-ui`, `@vicons/tabler`) provide all necessary primitives without adding any new npm packages.
