# 0004. 纯客户端图片处理工作台 (Image Studio) 响应式渲染管道与离线架构

## 状态
已接受 (Accepted)

## 背景与上下文
Ateng-Tools 作为纯前端离线开发者工具箱，现有工具涵盖代码生成、加解密、协议调试等，但缺少核心的位图与图像处理能力。
现代开发者高频面临图片缩放、裁剪、去除 EXIF 隐私敏感信息、格式转换（PNG/JPG/WebP/AVIF）、Favicon ICO 制作、防盗图文水印添加及压缩优化的诉求。
然而外部主流图片处理网站往往需要将图片上传至远程云端服务器，存在严重的代码截图、内部架构图或证件照片等敏感资产泄漏风险；若引入大型 WebAssembly 方案（如 Squoosh Wasm 库或 libvips），会导致打包产物体积膨胀几十兆，影响 GitHub Pages 的首屏加载体验。

## 架构决策
我们决定基于纯客户端 Canvas 2D / OffscreenCanvas 与响应式声明式管道（Non-destructive Render Pipeline）构建 **图片处理工作台 (Image Studio)**：

1. **非破坏性响应式流水线 (Non-destructive Pipeline)**：
   保留原始图像对象与数据源，将缩放、裁剪选区、滤镜调色、图文水印、导出格式与压缩率解耦为独立的响应式状态（State）。用户任意修改参数时，调度单向渲染管道在离屏 Canvas 重新合成，避免多步编辑过程中的画质累计劣化，并支持秒级参数撤销与调优。

2. **零数据外发与默认隐私安全 (Safe by Default)**：
   所有像素计算、裁剪切片与二进制导出均在浏览器沙箱内存中完成。所有导出图片默认 100% 抹除 EXIF（GPS、拍摄设备型号等），并提供只读式 EXIF 检查抽屉供按需透视。

3. **双视窗即时差分比对 (Before-After Split View)**：
   主工作区提供基于 Canvas 的原图与实时处理后效果同屏拖曳分割滑块，便于开发者在调整 WebP/JPEG 压缩质量时像素级审视画质与文字边缘。

4. **开发者专属扩展输出 (Developer-Oriented Exports)**：
   除支持 PNG、JPEG、WebP、AVIF 核心格式外，集成多分辨率 Favicon ICO 生成能力与一键 Base64 Data URL 提取能力，并提供主导调色板（Dominant Palette）颜色快速拾取。

5. **依赖克制与轻量级交互**：
   核心图形计算与编解码 100% 依托浏览器原生 Canvas 2D API，裁剪选区采用轻量级交互手柄方案，严格杜绝重型外部 WASM 依赖，保持极小构建体积与即开即用体验。

## 后果与影响
- **正面影响**：
  - 100% 保护开发者图片资产隐私，无任何网络 IO；
  - 非破坏性流水线带来极佳的参数调整自由度与无损重调能力；
  - 零重型依赖，打包体积轻盈，加载极快。
- **代价与权衡**：
  - 极端压缩率上限略低于多轮量化算法（如 pngquant 二进制 CLI）；
  - 超大分辨率图像（如 8K 以上）受限于客户端设备 GPU/内存与浏览器 Canvas 最大像素限制，需设置尺寸保护阈值（如软告警与缩放保护）。
