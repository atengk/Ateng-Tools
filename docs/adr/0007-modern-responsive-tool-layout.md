# 0007. 全局 ToolLayout 响应式宽屏容器与视口解耦架构设计 (Modern Responsive Tool Layout)

## 状态
已接受 (Accepted)

## 背景与上下文
Ateng-Tools 作为面向现代开发者的客户端工具箱，承载了包含代码编辑器、双栏差异比对、富文本排版、图形工作台、PDF 流水线与复杂数据转换在内的 100+ 款专业工具。

此前全站小工具统一挂载于 `src/layouts/tool.layout.vue`，存在历史遗留的视口布局死锁问题：
1. **视口宽度人为锁死在 600px**：
   `.tool-layout` 顶层样式声明了 `max-width: 600px; margin: 0 auto;`，导致在现代主流 1080P (1920×1080)、2K、4K 宽屏显示器上，面包屑与标题描述仅占据视口正中央极窄的一列，两侧留白高达 70% 以上。
2. **内容插槽子元素被深层强制限制为 600px**：
   `.tool-content` 样式中存在 `::v-deep(& > *) { flex: 0 1 600px; }`，直接强行劫持并重写了所有工具根容器的 `flex-basis`。这导致任何默认单卡片或标准排版的工具均被挤压在 600px 宽度内。
3. **多款复杂工具被迫引入 Hack 样式突破限制**：
   如 `image-studio`、`pdf-studio`、`curl-converter`、`sql-ddl-to-entity` 等需要宽屏展示的工具，不得不通过内联 `style="flex: 0 0 100%"` 或 `important:flex-1` 等侵入式 Hack 来强行击穿父级布局的约束，破坏了样式的一致性与代码整洁度。
4. **头部与内容对齐割裂**：
   在被迫突破 600px 的宽屏工具中，上方面包屑与标题依然被困在 600px 居中区域，而下方内容区铺满整个主视口，形成严重的视觉错位。

## 架构决策

经过深入分析与技术推演，确立以下架构决策：

### 1. 全局容器升维至宽屏响应式基线
- 将 `src/layouts/tool.layout.vue` 中的主容器基线统一调整为 `max-width: 1280px`（对齐现代桌面系统 7xl 断点规格），同时保持水平居中 (`margin: 0 auto`) 与安全自适应内边距 (`padding: 0 16px`)。
- 在 1280px 以内的移动端、平板或小窗口下，通过 `width: 100%` 保持完美的流式弹性自适应。

### 2. 彻底移除 `.tool-content` 内子组件宽度死锁
- 彻底废除 `.tool-content` 下的 `::v-deep(& > *) { flex: 0 1 600px; }` 样式规则。
- 将 `.tool-content` 调整为标准的响应式内容容器，子组件默认享有 `width: 100%; max-width: 1280px;` 的完整布局空间。
- 小工具视图层不再受外层容器宽度钳制，可依据自身业务形态自由采用单卡片、等分双栏、左右面板、网格排版或全宽画布。

### 3. 面包屑与工具头部与内容区左对齐
- 工具头部（面包屑导航、H1 工具标题、多语言描述、收藏按钮）与下方内容卡片保持左边缘在同一基准线上（`align-items: flex-start`）。
- 标题下方的装饰分隔线保持利落视觉过渡，整体呈现如同 VS Code / GitHub 工具台般专业开阔的现代工具体验。

### 4. 存量工具 Hack 样式渐进清理与自然兼容
- 移除全局死锁后，此前为突破 600px 而添加的 `style="flex: 0 0 100%"` 将自然兼容且不再成为必要依赖，全站工具无需任何修改即可立即获得宽屏自适应能力。

## 后果与影响

- **正面影响**：
  - **空间利用率飞跃**：在桌面宽屏下，SQL 解析、代码生成、Diff 对比、证书分析等核心工具的工作空间由 600px 扩展至 1280px，横向信息密度与可读性大幅提升；
  - **消除侵入式 Hack**：后续开发新工具无需在根节点追加 `style="flex: 0 0 100%"` 等防御性代码；
  - **视觉体验浑然一体**：头部面包屑、标题、描述与下方内容区域完全对齐，消除宽卡片与窄标题的不协调感；
  - **零副作用平滑过渡**：普通单卡片工具在 `1280px` 容器内以卡片形态展现或可通过组件自身配置 `max-w-xxx` 控制最佳阅读宽度，兼顾各类工具需求。
- **代价与权衡**：
  - 部分原本仅设计为单列小表单的简单小工具（如仅有一两个输入框），在全宽卡片模式下输入框较长，但在 Naive UI 网格与响应式栅格系统支持下排版依然自然整齐，后续可按需进行局部双栏微调。
