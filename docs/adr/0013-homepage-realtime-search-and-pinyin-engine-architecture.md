# 0013. 首页即时双轨搜索与客户端拼音索引架构 (Homepage Realtime Search & Client-Side Pinyin Engine)

## 状态
已接受 (Accepted)

## 背景与上下文
Ateng-Tools 包含 80 余款纯客户端离线小工具。此前首页仅依赖 **Tool Category Filter** 分类标签进行静态分组切换，缺乏在页面内容区直接进行文字实时搜索的能力；全站唯一的搜索入口为顶栏右侧的全局命令面板（`Ctrl+K` 模态弹窗）。
在中文开发者真实使用场景下，存在以下关键诉求与断层：
1. **首页浏览与查找割裂**：开发者在首页面对数十款工具卡片时，直觉期望能直接在页面中敲字实时过滤卡片，而不是被迫频繁唤起遮罩模态弹窗。
2. **中文拼音盲打缺失**：原有底层 Fuse.js 仅支持字面量匹配，当用户在未切换输入法或快速盲打状态下输入首字母（如 `ewm` 查找二维码、`mp` 查找 MyBatis、`zh` 查找实体转换）或全拼（`erweima`）时均无法命中。
3. **跨分类搜索孤岛**：当用户停留在某个分类标签时，若搜索词属于其他分类，容易出现“误判无结果”的盲区。

## 架构决策
经过全轮次 Design Tree 决策对齐，确立以下架构规范：

1. **首页搜索载体与版面定位 (Search Surface & Placement)**：
   - 在 Hero Banner 下方、**Tool Category Filter** 上方构建居中独立的 **Homepage Tool Search Filter**。
   - 保持常驻且自适应（移动端满宽、桌面端居中），桌面端呈现快捷键提示微标（`/` 聚焦、`Esc` 清空）。

2. **多维检索与拼音匹配引擎 (Matching Engine & Pinyin Token Indexer)**：
   - 引入轻量级零依赖纯客户端库 `pinyin-match`（~20KB），零外部网络请求，100% 在浏览器内存中运行。
   - 构建多维权重分级检索模型：
     `精准标题/路由命中 > 拼音首字母/全拼命中 > 英文 Keywords 命中 > 功能描述 Description 模糊命中`。
   - 利用 `pinyin-match` 返回的匹配字符起止区间，实现对工具标题的精准高亮切片。

3. **状态联动与作用域穿透 (State Synergy & Filter Scope)**：
   - **全库穿透检索**：只要检索框存在非空输入，检索逻辑自动穿透全站八大领域分类，**Tool Category Filter** 动态呈现“全部 (命中数)”，彻底消除分类孤岛。
   - **收藏夹自动让位**：非空检索态下，顶部“常用收藏区”平滑折叠隐去，全屏视线 100% 聚焦于匹配结果网格。
   - **上下文记忆恢复**：点击清除按钮（✕）或清空输入框时，收藏区平滑展开，分类标签无缝恢复至用户检索前停留在选中的具体分类。

4. **视觉线索与深度键盘流 (Visual Cues & Keyboard Ergonomics)**：
   - **高亮与命中溯源**：对卡片标题文本匹配段应用主题色微高亮（`text-primary font-semibold`）；若命中原因属于隐藏的拼音首字母或关键词，在卡片描述下方附带微型 **Match Cue Badge**（如 `匹配拼音: ewm`），保证检索结果可信可解释。
   - **极客全键盘操作**：
     - 首页任意空白区域按 `/` 键自动聚焦搜索输入框；
     - 搜索框内按 `Esc` 清空输入并失焦；
     - 搜索框内按 `Enter` 键直接打开当前排在首位的工具路由；
     - 支持方向键（`↓` / `↑`）在过滤后的卡片间移动焦点。

## 后果与影响
- **正面影响**：
  - 首页工具发现效率呈数量级提升，完美支持中文全拼、拼音首字母与英文缩写混合搜索；
  - 零侵入破坏全局 Command Palette，形成“页面内即时过滤 + 全局模态命令”互补的双轨体验；
  - 严格恪守 ADR-0001 纯离线安全原则，零数据外流。
- **代价与权衡**：
  - 引入了轻量库 `pinyin-match`（约 20KB 源码，Gzip ~8KB），需在打包依赖中规范声明；
  - 需要在 ToolCard 与 Home.page 之间建立高亮切片与匹配线索传递契约。
