# 0016. 日常生活与全栈开发常用工具扩展架构决策 (Daily & Full-Stack Tools Expansion)

## 状态
已接受 (Accepted)

## 背景与上下文
Ateng-Tools 经过持续迭代，已建立了涵盖 8 大领域分类（`Canonical Tool Taxonomy`）与 75 款独立小工具的纯客户端开发平台。在日常办公生活以及前后端全栈开发的高频实际场景中，仍存在若干高刚需、高频使用但此前未覆盖或较为分散的需求生态位：
1. **财务与日常票据合规**：开发人员与日常办公用户在拟定合同、填报发票、开发支付结算模块时，频繁需要进行阿拉伯数字与中文金融大写金额的精确双向互转与票据模板导出；
2. **公民身份信息校验与安全合规**：在全栈系统进行实名认证表单开发、用户数据脱敏处理以及本地调试时，迫切需要对 18 位身份证号码进行 MOD 11-2 合法性校验、行政区划与生理特征推演，同时坚守零隐私泄漏底线；
3. **团队协作与 Git 提交规范化**：全栈开发者在日常代码版本提交中，常常因记不清 Conventional Commits 规范类型与格式而产生非标准 Commit 信息，影响 CHANGELOG 自动生成；
4. **前端样式微调与响应式流体计算**：在视觉还原阶段，多重阴影拟物投影、毛玻璃模糊滤镜、不规则圆角以及 px/rem 流体排版计算往往分散在不同网站，缺少一站式纯离线调试工坊。

为满足上述诉求，本决策对新增功能矩阵、架构分层、分类落位及依赖策略进行统一定调。

## 架构决策

### 1. 首批工具矩阵与领域分类落位 (Taxonomy Alignment)
严格遵循 [ADR-0006](0006-canonical-tool-taxonomy-and-category-consolidation.md) 的 8 大规范分类拓扑，首批纳入建设的 4 款工具及其落位如下：
- **`rmb-amount-converter` (人民币大写金额转换器)**：落位于 **`converter`**（格式转换）分类，专注金融数码与文本的双向无损转换；
- **`chinese-id-card-inspector` (中国居民身份证透视器)**：落位于 **`security`**（加密安全）分类，强调合规性校验算法、防欺诈识别与多模式敏感脱敏保护；
- **`conventional-commits-generator` (规范化 Git 提交生成器)**：落位于 **`dev`**（开发运维）分类，提供引导式提交信息与跨平台命令行组装；
- **`css-visual-studio` (CSS 视觉工坊)**：落位于 **`dev`**（开发运维）分类，集成前端样式高频调参微模块与即时渲染导出。

### 2. 纯客户端离线与极致体积控制 (Zero-Leakage & Minimal Footprint)
严格继承 [ADR-0001](0001-client-side-dev-tools-architecture.md)，所有计算与解析 100% 在浏览器内存中执行：
- **身份证行政区划紧凑字典**：为防止引入全量 3000+ 区县数据库导致体积膨胀数十倍，采用优化压缩的前 4 位地级市字典（覆盖全国省及 300+ 地级市/直辖区），将字典体积严格控制在 6~8KB 以内；
- **纯原生算法无依赖**：人民币大写状态机、MOD 11-2 校验、Conventional Commits 词法排版与 CSS 样式计算全部采用原生 TypeScript 编写，零外部运行时 npm 依赖。

### 3. 功能特性与边界规范 (Feature Specifications)

#### 3.1 人民币大写金额转换器 (`rmb-amount-converter`)
- **双向互转**：支持数字转大写，以及大写金额反向语法解析还原为数字；
- **央行规范**：支持万亿级整数，角/分两位小数精确处理，负数支持，自动处理连续零与单位进阶规则；
- **票据模板**：提供合同报销规范模板一键复制。

#### 3.2 中国居民身份证透视器 (`chinese-id-card-inspector`)
- **MOD 11-2 校验**：严格计算 18 位身份证校验码，呈现加权求和明细；
- **特征推演**：提取出生日期、周岁年龄、生肖、星座、生理性别；
- **历史兼容与联调辅助**：支持 15 位老身份证升级 18 位，提供用于开发测试的合法虚拟号码生成器；
- **多模式脱敏**：支持前 6 后 4、隐藏生日等常用合规掩码格式一键导出。

#### 3.3 规范化 Git 提交生成器 (`conventional-commits-generator`)
- **标准 Type 预设**：集成 11 种标准语义化类型（`feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`），配齐清晰中文场景说明；
- **作用域记忆**：支持自定义 Scope 输入，结合 `localStorage` 缓存常用历史；
- **破坏性变更显式引导**：一键切换 `!` 标识与 `BREAKING CHANGE:` Footer 注解；
- **命令防御性转义**：一键生成纯提交文本及适用于 PowerShell / Bash 的防注入双引号命令。

#### 3.4 CSS 视觉工坊 (`css-visual-studio`)
- **四大微模块选项卡**：
  1. Box-Shadow 多层投影与内阴影可视化；
  2. Glassmorphism 毛玻璃拟态与边框高光；
  3. Fancy Border-Radius 8 点不规则水滴曲面圆角；
  4. CSS Units & Fluid `clamp()` 响应式字号计算；
- **双轨导出**：即时输出纯净原生 CSS 及 UnoCSS / Tailwind 实用原子类。

### 4. 标准工程五件套与国际化准则 (Standard 5-Layer Blueprint & i18n)
所有 4 款小工具严格按照工程规范分层实现：
- 视图层（`<name>.vue`）：基于 Naive UI 2.35 与全站设计令牌构建，按钮居中，响应式双栏排布；
- 服务层（`<name>.service.ts`）：设计为无状态纯函数，与 DOM/Vue 上下文彻底解耦；
- 单元测试（`<name>.service.test.ts`）：Vitest 100% 覆盖关键边界分支；
- 类型契约（`<name>.types.ts`）：强类型约束；
- 国际化（`locales/zh.yml` / `locales/en.yml`）：100% 同步中文与英文完整交互词条。

## 后果与影响

- **正面影响**：
  - 填补了全栈开发者在日常票据、身份校验、Git 提交与前端视觉调参等最高频场景的工具空白；
  - 维持 100% 纯客户端离线隐私，零数据外流；
  - 保持全站极致轻量，未引入任何重型外部第三方库，冷启动速度不受任何影响。
- **代价与权衡**：
  - 身份证区划由于字典体积限制采用地级市覆盖，未能细化至县级三级区划（如需县级可在后续版本按需渐进加载）。
