# 0010. 纯客户端跨设备 P2P 局域网快传架构决策 (P2P File Transfer)

## 状态
已接受 (Accepted)

## 背景与上下文
在跨设备开发与日常使用中，用户频繁需要将手机中的照片、应用安装包（APK）、测试截图、真机日志或临时文本/URL 发送到电脑端，或从电脑端反向投送到手机。
传统方案多依赖第三方微信/QQ 文件传输助手（有泄露风险且文件被压缩）或本地伴侣软件（如 LocalSend，需安装原生客户端）。
在 Ateng-Tools 托管于 GitHub Pages 的纯静态、纯客户端离线架构下，浏览器沙箱无法直接监听操作系统 TCP/HTTP 端口充当本地文件服务器。需要构建一套既符合零数据泄漏底线，又能提供类似 AirDrop 般“扫码即连”体验的跨设备传输方案。

## 架构决策

### 1. 传输通道：基于 WebRTC DataChannel 的端到端加密直连
采用 WebRTC DataChannel（基于 SCTP over DTLS 协议）。对等端建立连接后，数据在两台设备之间直接走局域网或 P2P 加密隧道传输，绝不通过任何中继服务器转发文件内容，坚守零数据泄漏红线。

### 2. 信令握手：双模混合架构 (Hybrid Signaling)
针对无后端静态托管环境，提供两种信令握手模式：
- **信令中继秒连模式 (Signaling Broker)**：默认集成轻量信令（如 PeerJS 官方云节点，并支持用户配置私有信令节点与 STUN/TURN 服务器）。电脑生成房间二维码，手机使用系统相机或微信扫码打开对应带有房间参数的页面即可毫秒级完成信令匹配并直连。
- **纯离线气隙模式 (Air-Gapped Exchange)**：在严苛隔离内网或完全无外网环境下，提供纯离线双向二维码/文本交换 SDP 握手机制，100% 零外网请求。

### 3. 数据流水线：分块流式传输与背压流控 (Chunked Streaming Transceiver)
为防止移动端浏览器（尤其是 iOS Safari）内存溢出（OOM），禁止一次性全量加载超大文件：
- 发送端按 16KB~64KB 进行切片流式分发；
- 监听 `bufferedAmountLowThreshold` 与 `bufferedAmount` 实施背压流控，防止对端缓冲区被撑爆；
- 接收端按有序包序重组，组装完成后以 `Blob` 触发直接下载或内存暂存。

### 4. 分类归属：落位 `network` (网络与 Web)
依据 [ADR-0006](0006-canonical-tool-taxonomy-and-category-consolidation.md)，该工具底层依托 WebRTC P2P 数据通道与局域网网络通信，其本质是设备间的网络互联与协议传输，统一归入 `network` 领域分类。

### 5. 功能边界：双向文件传输与轻量剪贴板同步
不仅支持手机单向投送电脑，同时打通电脑向手机的反向传输，并提供轻量级文本/URL 实时同步能力，极大提升高频跨端操作效率。

## 后果与影响
- **正面影响**：
  - 免装任何 App，任何设备只要有现代浏览器即可随时收发；
  - 局域网直连速度不受外网带宽瓶颈限制；
  - 核心传输数据端到端加密，兼顾便捷性与最高级别隐私安全。
- **代价与权衡**：
  - 在复杂对称型 NAT 或跨非同源局域网时，若无 TURN 中继可能穿透失败；
  - 双模设计需要分别维护信令中继状态机与离线气隙状态机。
